1. 이 도구는 무엇인가

LiteLLM은 여러 AI 모델 제공자(OpenAI·앤트로픽·구글 등)를 하나의 창구로 묶어 주는 중개 서버입니다. 공식 소개 문구 그대로 "100개 이상의 LLM을 OpenAI 형식으로 호출하는 프록시 서버"입니다. 도구마다 제공자별 키를 따로 넣는 대신, 주소 하나 + 키 하나만 등록하면 뒤에 어떤 모델이 붙어 있든 같은 방식으로 씁니다.

이 교육에서 LiteLLM을 쓰는 이유는 세 가지입니다.

이유무슨 뜻인가
키를 여러 개 안 받아도 된다수강생은 실습용 키 하나만 받습니다. OpenAI·앤트로픽 계정을 각자 만들 필요가 없습니다
비용·사용량이 주관사 쪽에서 관리된다실습용 키에는 사용 한도가 걸려 있습니다. 개인 카드로 결제할 일이 없습니다
등록 방법이 단순하다헤르메스에는 "OpenAI 호환 주소 + 키"를 넣는 사용자 지정 엔드포인트 칸이 있습니다. 도구마다 지원 여부가 다르므로 5-3을 보세요

법률 업무 예시 — 서면 초안은 A 모델, 긴 계약서 검토는 B 모델이 낫다고 판단했을 때, 도구를 다시 설치하거나 키를 새로 발급받는 대신 모델 이름만 바꿔 같은 주소로 요청하면 됩니다. 도구 설정을 매번 뜯어고치지 않아도 됩니다.

"프록시", "엔드포인트", "게이트웨이"가 다 같은 말인가요?
이 문서에서는 사실상 같은 것을 가리킵니다. 내 도구가 AI에게 말을 걸 때 찾아가는 주소 입니다. 도구마다 그 칸의 이름이 다릅니다 — Base URL, API Base, 사용자 지정 엔드포인트, Custom endpoint, OpenAI 호환 주소. 전부 같은 칸이고, 전부 이 문서 2절의 주소를 넣습니다.

🔐 보안 원칙 (전 과정 적용)

  • 실습용 키를 문서·메모장·카카오톡·메일에 적지 마세요. 화면에서 바로 붙여넣고 "어디에 보관했는지"만 기억합니다.
  • 이 문서에 키를 적어 두지 마세요. 이 파일은 다른 수강생과 공유되는 교육 자료입니다.
  • 질문할 때 키가 보이는 화면을 캡처해 보내지 마세요. 키 부분을 가리고, 오류 문구만 전달합니다.
  • 키가 노출됐다고 판단되면 즉시 Facilitator에게 폐기를 요청하세요. 개인이 폐기할 수 없습니다 (8-3).
  • 이 키는 실습 전용입니다. 실제 의뢰인 자료·사건번호를 넣는 작업에 쓰지 마세요. 요청 내용은 주관사 서버를 거쳐 갑니다.
  • 회사 보안 프로그램이 연결을 막으면 임의로 끄거나 예외 등록하지 말고 담당자에게 문의하세요.

  • 복사할 때 앞뒤에 공백이나 줄바꿈이 딸려 오는 것이 인증 실패 원인 1위입니다. 4단계에서 이걸 자동으로 걸러 줍니다.

4단계 — 키를 이 창에만 담기

아래를 붙여넣고 Enter.

PowerShell에 붙여넣기
$key = (Read-Host "실습용 키를 붙여넣고 Enter").Trim()
👀

예상 결과: 실습용 키를 붙여넣고 Enter: 가 표시되며 입력을 기다립니다. 여기에 키를 붙여넣고(Ctrl + V) Enter 를 누르면 아무 메시지 없이 다음 줄로 돌아옵니다.

이 방법을 쓰는 이유 — 명령 줄에 키를 직접 타이핑하면 키가 PowerShell 명령 기록 파일에 그대로 저장됩니다. Read-Host 로 받은 입력은 기록에 남지 않습니다. 뒤의 .Trim() 은 앞뒤에 딸려 온 공백·줄바꿈을 자동으로 잘라 냅니다.

  • 이 $key 는 지금 연 창에서만 유효합니다. 창을 닫으면 사라집니다 (그게 정상이고 안전합니다).
  • 붙여넣는 순간 키가 화면에 보입니다. 이 단계에서는 화면 공유·녹화를 하지 마세요.

제대로 담겼는지 확인 (키 값은 보여 주지 않습니다)

PowerShell에 붙여넣기
"글자 수: $($key.Length) / sk- 로 시작: $($key.StartsWith('sk-'))"
👀

예상 결과: 글자 수: 40 / sk- 로 시작: True 처럼 나옵니다. 글자 수는 키마다 다릅니다.

⚠️

이렇게 나오면 오류

  • 글자 수: 0 → 키가 안 담겼습니다. 4단계를 다시 실행하세요.
  • sk- 로 시작: False → 키가 아닌 다른 값(주소 등)을 붙여넣었거나, 앞쪽에 글자가 섞였습니다. 다시 복사해 4단계를 반복하세요.

4. 연결 확인 (30초)

같은 PowerShell 창에 아래 한 줄을 붙여넣고 Enter.

PowerShell에 붙여넣기
try { (Invoke-RestMethod -Uri "https://aiagentguild-litellm-265093816090.asia-northeast3.run.app/v1/models" -Headers @{ Authorization = "Bearer $key" }).data.id } catch { $_.ErrorDetails.Message }
👀

예상 결과: 쓸 수 있는 모델 이름이 한 줄에 하나씩 나옵니다. 여기까지 되면 연결 성공입니다.

나온 모델 이름 중 하나를 메모해 두세요. 5절에서 도구에 등록할 때, 6절에서 테스트할 때 그 이름이 필요합니다. (모델 이름은 비밀이 아니므로 적어 둬도 됩니다.)

💡 try { ... } catch { ... } 를 왜 씌우나요? PowerShell은 요청이 거절되면 (401) 권한 없음 같은 번호만 보여 주고, 서버가 보낸 진짜 이유는 감춥니다. catch 부분이 그 서버 문구를 꺼내서 보여 줍니다. 원인이 키 누락인지 키 오류인지는 그 문구로만 구별됩니다.

⚠️

이렇게 나오면 오류 — 빨간 글씨에 (401) 권한 없음 만 보이면, 그 아래(또는 그 대신) 나오는 서버 문구로 증상 1과 2를 가르세요.

화면에 나오는 문구볼 곳
Authentication Error, No api key passed in.7절 증상 1
Invalid proxy server token passed / Unable to find token in cache7절 증상 2
이름을 확인할 수 없습니다 / 작업 시간이 초과되었습니다7절 증상 4
(401) 이라는 번호만 보이고 서버 문구가 안 보인다3절 4단계로 돌아가 $key 확인 → 다시 위 명령 실행

💡 모델 목록이 무엇이 나올지는 이 문서에서 미리 알려 드릴 수 없습니다. 서버에 어떤 모델이 붙어 있는지는 주관사가 그때그때 정하며, 목록 조회 자체가 키 없이는 안 됩니다. 위 명령의 결과가 곧 정답입니다. 목록이 비어 있으면 Facilitator에게 알리세요.

💡 테스트 문장을 영어로 둔 이유: PowerShell에서 한글을 직접 보내고 받으면 창에서 글자가 깨져 보일 수 있습니다. 연결 문제가 아니라 표시 문제이므로, 이 확인용 테스트는 영어로 하고 한글 작업은 도구 안에서(6-1) 하세요.

7. 문제 해결

💡 증상 1과 2는 화면에 똑같이 (401) 권한 없음 으로만 보일 수 있습니다. 어느 쪽인지는 4절 명령의 catch 가 보여 주는 서버 문구로 갈립니다. 문구가 안 보이면 4절 명령을 try { ... } catch { ... } 형태 그대로 다시 실행하세요.

증상 1 — Authentication Error, No api key passed in.

  • 원인: 키가 아예 전달되지 않았습니다. ① PowerShell 창을 새로 열어 $key 가 비었거나(창을 닫으면 사라집니다), ② 도구의 API Key 칸이 비어 있습니다.
  • 해결: PowerShell이라면 3절 4단계를 다시 실행해 $key 를 담고(확인 명령으로 글자 수: 0 이 아닌지 보세요) 4절을 재시도합니다. 도구라면 5절을 다시 하며 키 칸이 실제로 채워졌는지 확인하세요.

증상 2 — Invalid proxy server token passed / Unable to find token in cache or LiteLLM_VerificationTokenTable

  • 원인: 키가 전달은 됐지만 서버가 모르는 값입니다. ① 복사가 잘려 일부만 들어갔거나, ② 앞뒤에 공백·줄바꿈이 섞였거나, ③ 다른 서버용 키이거나, ④ 이미 폐기·만료된 키입니다.
  • 해결: ① 3절 4단계의 확인 명령으로 글자 수와 sk- 시작 여부를 먼저 봅니다. ② 키를 처음부터 다시 복사해 4단계를 반복합니다 (.Trim() 이 공백은 걸러 줍니다). ③ 그래도 같으면 Facilitator에게 오류 문구만 전달하고 키 상태 확인을 요청하세요 — 키 값 자체는 메신저로 보내지 마세요.

증상 3 — 모델을 찾을 수 없다는 400 오류 / 모델 이름 관련 오류

  • 원인: model 에 넣은 이름이 이 서버에 없는 값입니다. 다른 교육 자료나 인터넷에서 본 모델 이름(예: 일반적인 제공자 모델명)을 그대로 넣으면 이렇게 됩니다. 이 서버에서 쓸 수 있는 이름은 4절 목록에 나온 것뿐입니다.
  • 해결: 4절 명령을 다시 실행해 목록을 확인하고, 거기 있는 이름을 글자 그대로 다시 넣으세요(대소문자·하이픈까지 동일하게). 목록이 비어 있으면 Facilitator에게 알리세요.
  • ⚠️ 이 경우의 정확한 오류 문구는 유효한 키가 있어야 확인할 수 있어 작성 시점에 검증하지 못했습니다. 문구가 달라도 "모델(model)"이라는 단어가 보이면 이 증상입니다.

증상 4 — 연결이 아예 안 된다 (사이트에 연결할 수 없음 / 이름을 확인할 수 없습니다 / 작업 시간이 초과되었습니다)

  • 원인: 사내 방화벽·프록시가 외부 주소를 막고 있거나, 네트워크가 불안정합니다.
  • 해결: ① 먼저 3절 1단계(브라우저로 /health/liveliness)를 열어 봅니다. 브라우저는 되는데 PowerShell·도구만 안 되면 프로그램별 프록시 설정 문제입니다. ② 휴대폰 테더링으로 바꿔 재시도합니다 (교육장에서 가장 빠른 확인법). ③ 테더링에서는 되고 회사 와이파이에서만 안 되면 사내 차단입니다 — 보안 프로그램을 끄거나 프록시 설정을 임의로 바꾸지 말고 전산·보안 담당자와 Facilitator에게 함께 알리세요.

증상 5 — 응답이 느리거나 429 / 한도·예산 초과 안내가 뜬다

  • 원인: 실습용 키에는 사용 한도가 걸려 있습니다. 여러 명이 동시에 요청하거나 긴 문서를 반복해서 넣으면 일시적으로 막힐 수 있습니다.
  • 해결: ① 1~2분 기다린 뒤 다시 시도합니다. ② 같은 요청을 반복해서 보내지 마세요(한도를 더 빨리 씁니다). ③ 계속 막히면 Facilitator에게 오류 문구와 시각을 전달하세요. 다른 사람의 키를 빌려 쓰지 마세요 — 누가 무엇을 했는지 추적이 불가능해집니다.
  • ⚠️ 한도 초과 시의 정확한 문구·수치는 이 서버의 설정에 따라 달라 작성 시점에 확인하지 못했습니다. 구체적인 한도는 당일 안내를 따르세요.

증상 6 — 답은 오는데 PowerShell 창에서 한글이 깨져 보인다

  • 원인: PowerShell 창의 글자 표시 방식(인코딩) 문제입니다. 연결·키 문제가 아닙니다.
  • 해결: 확인용 테스트는 6-2처럼 영어로 하고, 한글 작업은 도구 안에서(6-1) 하세요. 도구 화면에서 한글이 정상으로 보이면 아무 문제 없습니다.

8-3. 키 폐기·재발급 요청 (개인이 할 수 없습니다)

실습용 키의 폐기·재발급은 서버 관리자 권한이 필요합니다. 수강생 본인은 할 수 없습니다.

  • 키가 노출됐다고 판단되면 즉시 Facilitator에게 폐기를 요청하세요. 늦게 알리는 것이 노출 자체보다 더 큰 문제입니다.
  • 요청할 때 키 값을 메신저에 붙여넣지 마세요. "누구에게 받은 실습용 키", "언제 어떤 상황에서 노출됐는지"만 전달하면 관리자가 찾아 폐기합니다.
  • 교육이 끝나면 별도 요청 없이도 키가 정리될 수 있습니다. 정리 시점은 당일 안내를 따르세요.

다른 연결 방법

본문의 표준 경로(PowerShell 확인 → 도구 마법사 등록)를 권장합니다. 아래는 해당되는 경우에만 보세요.

① curl.exe 로 확인 — Windows 10/11에는 curl.exe 가 기본으로 들어 있습니다. Invoke-RestMethod 가 익숙하지 않다면 대신 쓸 수 있습니다. (실습용키 를 실제 값으로 바꿔야 하므로 명령 기록에 키가 남습니다. 공용 PC에서는 쓰지 마세요.)

PowerShell에 붙여넣기
curl.exe -H "Authorization: Bearer 실습용키" https://aiagentguild-litellm-265093816090.asia-northeast3.run.app/v1/models

② 환경변수로 두기 — 많은 도구가 OPENAI_BASE_URL·OPENAI_API_KEY 를 자동으로 읽습니다. 도구에 설정 칸이 없을 때만 쓰세요.

PowerShell에 붙여넣기
